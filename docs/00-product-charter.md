# OpenClaw Workbench 产品章程

## 1. 产品定义

OpenClaw Workbench 是面向 OpenClaw 的本地 Agent 工作台：把模型配置、项目工作区、Agent 执行、工具/MCP、权限审批、差异审阅、验证和恢复组织成一个可安装、可诊断、可升级的产品。

它不是 OpenClaw 核心的替代品，也不是把聊天窗口套在 Gateway 外面的 Demo。

## 2. 目标用户

- 个人开发者：希望在本地项目中安全使用 Agent。
- 小型团队：希望统一模型、工具、权限和审计规范。
- 内网研发环境：需要本地运行、可控外联和可追踪操作。

## 3. 第一版必须解决的问题

1. 用户安装后无需手改复杂配置即可完成首次启动。
2. 用户能明确知道 Agent 当前能读什么、改什么、执行什么。
3. 代码修改必须可预览、可批准、可验证、可回滚。
4. 模型、工具和 MCP 失败时必须可诊断，不能静默吞错。
5. 现有 OpenClaw 配置不得被覆盖；导入必须备份并可撤销。
6. 所有高风险动作必须留下结构化审计记录。

## 4. 第一版范围

### 包含

- 本地工作区选择与安全边界
- 模型配置向导和连接测试
- Ask / Plan / Code 三种 Agent 模式
- 文件搜索、读取、差异预览
- Patch 审批、哈希校验、应用和回滚
- 受控终端执行、取消、超时和结果记录
- MCP Server 清单、健康检查和工具级授权
- 本地诊断、日志导出和配置备份

当前配置切片只管理工作区内的 JSON 配置副本；真实用户目录中的 OpenClaw 配置导入仍需显式路径授权和平台密钥存储设计，不能把当前切片误认为已接管生产配置。模型档案切片同样只保存元数据和 SecretRef 引用，不解析密钥或自动连接供应商。

### 暂不包含

- 公网 Bridge
- 云端账号和团队协作后台
- 多人同时编辑
- 自动安装未经审核的 Skill 或 MCP
- 无审批的外部消息发送、生产变更和高风险命令

## 5. 非目标

- 不承诺兼容所有第三方模型和 MCP Server。
- 不把 ShunCode 的宣传描述视为实现证明。
- 不绕过 OpenClaw、操作系统或宿主的安全边界。
- 不在第一版追求功能数量，而以可恢复和可审计为准。

## 6. 产品成功标准

在干净环境中，目标用户能够完成：安装 → 首次诊断 → 配置模型 → 打开工作区 → Ask 阅读 → Plan 产出方案 → Code 预览并批准补丁 → 运行测试 → 查看审计记录 → 回滚改动；整个流程无手工修改生产配置。

## 7. 结论分层

- **已确定**：产品范围和安全原则。
- **待验证**：OpenClaw 当前稳定集成接口、跨平台运行方式、MCP 接入边界。
- **禁止假设**：任何未通过当前版本实测的内部 API、Bridge 安全能力和第三方组件许可证。
